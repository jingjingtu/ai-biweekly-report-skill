# 原始视觉参考索引

本目录保存用户明确要求纳入公开 GitHub 仓库的 18 张原始 PNG。生成长卷前，按内容类型打开最接近的 2–4 张原图审查；不能只读取文字摘要，也不能把原图直接当作新报告的业务事实。

## 使用优先级

1. 当前任务材料决定事实与结论。
2. `b-end-history` 决定 B 端汇报的推理顺序、证据密度与章节组织。
3. `other-team` 只提供视觉构图、节奏、层级和装饰方式。
4. 同时参考多张图时，提炼可组合的版式语法，不复制整套页面骨架。

用户 B 端历史稿的稳定审美不变量是：大标题统一左对齐、章节内容共享固定左右边界、主绿负责结论、辅助色只做局部编码、大容器先建立层级、内部模块再变化。不能把“参考多张图”误解成每节标题方向和网格都不同。

## 审查记录要求

生成前在工作记录中写明：

```yaml
visualReferences:
  - file: <相对路径>
    usedFor: <构图 / 节奏 / 证据组织 / 装饰语法>
    reused: <实际复用的结构>
    rejected: <主动舍弃的个案元素>
```

至少回答：原图的左边距和标题基线是什么、标题/正文/标签层级如何、主容器圆角和描边如何、主绿与辅助色比例如何、本节的视觉重心是什么、内容区与上一节有什么变化、装饰是否承载信息、哪些事实禁止带入。不能只记录“黑绿科技风”。
