# 视觉样例审查与版式基准

## 使用范围

本文件来自其他团队视觉样例，记录可复用的共同视觉规律、条件版型和不可照搬项。它是 **视觉风格参考**，不决定 B 端汇报的内容顺序。B 端任务必须先按 [B 端历史汇报内容标准](b-end-content-standard.md) 组织推理，再从本文件选择承载方式。12 张用户提供的原始 PNG 已收录在 [原始视觉参考索引](visual-reference-index.md)，生成时必须审查相关原图，不能只依赖本文件摘要。

优先级为：当前事实材料 → B 端内容逻辑 → 本文件的视觉形式。生成前如果用户提到“标准样例”“按之前的样式”或指定其中一个视觉样例，必须读取本文件并选择匹配的样例原型，不能仅凭“黑底科技风”自由发挥。

样例中的品牌、项目名、截图、头像、Logo、百分比和工期属于原案例事实，不是默认内容。除非当前材料能提供来源、日期与统计口径，否则只能复用结构，不能复用数字或结论。

## 审查方法

- `A / 共同标准`：至少 4 份样例重复出现，作为默认规则。
- `B / 条件模式`：2–3 份样例出现，只在内容条件匹配时使用。
- `C / 个案表达`：只在 1 份样例出现，不能自动升级为通用规则。
- 所有 6 份样例均为 1920px 宽长卷；高度、章节数量和内容密度随叙事变化，不设固定总高度。
- 下表的“可复用”指信息结构和视觉组织，不代表可以复制样例原文或业务数据。

## 五角色审查结论

- **架构师**：样例共同指向独立的 `long-scroll` 画布格式，不能覆盖现有 `slides`；用原型和证据等级分层后，两种格式可以共享内容模型而保持渲染边界清楚。
- **设计师**：黑底、主绿、终端眉题、三步路径、截图证据和进度长列表具有稳定共性；漫画、播放按钮、中央图标和具体配色组合只属于条件或个案表达。
- **产品经理**：这些样例只能支持视觉层面的“目标—变化—路径—进度—证据—下期”结构；B 端内容仍以历史汇报中的验证闭环为准，案例百分比不能脱离来源复用。
- **研发**：标准需落到 `format`、`sampleArchetype`、`sectionLayoutPlan` 和可运行渲染分支，而不是只写审美描述；原始 PNG 是视觉审查资产，但不能成为渲染时必须嵌入的输出依赖。
- **测试**：必须分别回归 1920 × 1080 分页和 1920px 连续长卷，并验证样例事实不会自动进入新报告。详细检查项见 [五角色审查清单](review-checklist.md)。

## A 级共同标准

### 1. 输出画布

- 标准长卷使用 `format: long-scroll`：宽度固定 1920px，总高度由章节内容决定。
- 长卷不是把很多 16:9 页面用 40px 灰色缝隙拼接；章节在同一近黑画布中连续衔接，允许深绿或深蓝整段换底形成节奏。
- 独立演示页仍使用 `format: slides`：每页固定 1920 × 1080。长卷和演示页必须显式区分，不能把长卷密度压进单张 1080px 页面。
- 长卷建议由 4–8 个叙事章节组成；总高度不作为质量指标。

### 2. 叙事主轴

默认从下列顺序中选择必要章节，不强制全部出现：

1. **目标或专项命题**：一句话说明要形成什么可复用能力。
2. **变化或方法**：Before/After、传统/AI、旧流程/新流程，说明本期改变了什么。
3. **实现路径**：优先用三阶段或三步链路表达能力沉淀、验证和业务落地。
4. **进度盘点**：按能力族或业务族分组，展示状态、负责人、节点和完成口径。
5. **证据案例**：使用真实截图、产物、对比、流程记录或可验证链接证明结论。
6. **下周期计划**：写清里程碑、交付物和验收标准；存在会议决策时追加明确 Ask。

标题必须表达判断或变化，不能只写“项目进展”“工作汇报”。封面或首章使用大号白色主标题，并将最关键结论短语标为主绿。

### 3. 证据优先

- 产品截图、手机 Mockup、生成结果、测试记录或设计资产是信息主体，不是装饰。
- 每组截图必须有一句图注说明“它证明了什么”；只有文件名或工具名不算证据。
- 案例优先展示 `输入/约束 → AI 或 Skill 处理 → 可检查输出 → 业务效果`。
- 对比型章节必须确保两侧口径一致；若展示工时或提效，要同时给出基线、样本范围、来源和统计日期。
- 样例中的 `30%+`、`≥70%`、`约 5 分钟` 等不能作为模板默认值。

### 4. 信息层级与节奏

- 顶部可使用 24px 以上的终端眉题，例如 `> AI Design / biweekly.md`，它是定位信息，不抢主标题。
- 每个章节只承担一个主要判断；章节标题、解释句、主证据、结论条依次降级。
- 章节之间使用充足黑色留白、细分隔线或整段换底；避免所有内容都放入同权卡片。
- 关键路径或阶段结论可使用全宽横条收束，横条只写一句可复述结论。
- 三列路径是默认高频结构：步骤编号、动作、证据和结果从左到右排列，并用箭头说明关系。

### 5. 视觉系统

- 画布：近黑 `#030605`；一级深色容器采用深绿或深蓝，而非灰色卡片海。
- 主色：荧光绿 `#00F58A`，用于主线、核心结论、当前阶段和关键数字。
- 辅色：青色表示验证/连接；紫色表示 Skill/生成能力；粉色表示差异、例外或需要注意的分支。橙色只在确有“下一阶段”语义且不与粉色冲突时局部使用；状态仍必须有文字标签。
- 文字：中文标题使用高字重无衬线；英文、路径和状态使用等宽字体。
- 卡片：细描边、8–16px 圆角、克制实底；不使用大面积渐变、随机光球和纯装饰发光。
- 长卷工作值：水平安全边距 72–96px，主章节上下留白 80–160px，网格间距 24–40px。具体值应按截图比例与内容量校准。

### 6. 进度盘点

- 先按能力族或业务族分组，再列 Skill/模块；不能把不同层级混成同一个卡片网格。
- 每个条目至少包含名称、当前状态和下一门槛；有排期时增加计划完成日，有负责人时增加姓名或角色。
- 百分比只在存在明确分母和验收标准时使用。否则使用 `DONE / VERIFY / NEXT / BLOCKED / BASELINE`。
- 右侧大百分比或 `NEXT` 是扫描锚点，左侧任务清单负责解释依据，两者不能互相矛盾。

## B 级条件模式

| 内容条件 | 采用结构 | 不适用时不要使用 |
|---|---|---|
| 有旧流程与新流程证据 | `before-after` 对照 + 新流程三阶段 | 只有愿景、没有真实过程时 |
| 有 2–5 个同口径数字 | 一行指标带 | 数字缺来源、口径不一致时 |
| 有明确依赖关系的 3 步 | 三列路径 + 箭头 + 全宽结论条 | 只是 3 项并列任务时 |
| 有多个 Skill 或能力族 | 能力组合图 + 分组进度长列表 | 只有单一能力时 |
| 有多张真实产出 | 画廊网格 + 代表样例放大 | 图片重复、无法说明价值时 |
| 有阶段版本门槛 | 三阶段路线/时间轴 | 仅按日期罗列任务时 |
| 有下周期明确交付 | 三张里程碑卡 | 负责人、交付物和验收均缺失时 |

## C 级个案表达与不可照搬项

- 漫画式工作流插图、视频播放按钮、中央文件夹图标、头像和具体 Logo 都是个案表达，不是强制组件。
- 具体业务场景、产品界面和品牌术语只能来自当前材料。
- 样例中的所有结果数字先视为“案例主张”，不能据此推导模板的真实指标。
- 不从视觉样例反推事实，不把设计稿中的拼写、时间、百分比或项目状态视为已验证数据。
- 压缩预览不用于读取细小文字或判断业务事实；细节不清楚时回到原始文件或向用户标记待确认。

## 原型选择

- `strategy-progress`：管理层同步目标、方法变化、路径和组合进度。
- `capability-roadmap`：重点说明某项能力如何分阶段建设、内测和训练。
- `capability-system`：适合从生产方式升级讲到系统化能力与案例证明。
- `portfolio-operations`：适合多业务场景、多 Skill、多部门复用的组合盘点。
- `b-end-transformation`：适合 B 端页面生产、平台复用和效率验证。
- `gallery-case`：适合单一视觉生成 Skill 的价值对比和成果画廊。

若两个原型都符合，优先选择与“会议要推动的决策”最相关的一种；其余结构作为次级章节，不混合两个完整封面或两套进度系统。

## 样例一致性验收

- 已明确 `format` 和 `sampleArchetype`，没有把长卷当成 16:9 单页。
- 用户提供多种版式样例或长卷达到 4 个主要章节时，已记录 `sectionLayoutPlan`；至少 3 种主布局被实际使用，相邻章节没有复用同一骨架。仅换色、换标题或调整卡片数量不得计为通过。
- 使用用户 B 端历史样例时，所有章节标题统一左对齐，并与眉题、说明和一级内容容器共享左侧基线；版式变化只发生在标题下方。
- 章节大标题以白色为主体、主绿强调关键结论；B 端汇报不使用红色，差异或例外使用小范围粉色标记，不得成为大标题主色。
- 审查用户扩展样例时，提炼低对比渐变表面、分层背景、阶段轨道、分支/汇聚连接和证据载体；不能退化为只有线条描边的卡片拼接。
- 已记录实际审查的原始 PNG、复用结构、装饰语法与主动舍弃项；不能只写“参考黑绿科技风”。
- 长卷只有一个连续根画布，小节有独立大标题和内容区，但没有页与页之间的拼接缝或独立画板间隔。
- 所有可见文字均不小于 24px；每章使用 1–3 种内容相关的克制装饰，且相邻章节的装饰组合不完全相同。
- 同级模块的上下边线、列宽、间距和状态右边线经过坐标检查，没有“看起来差不多”的近似对齐。
- 首屏在 10 秒内可读出专项目标、核心变化和当前阶段。
- 至少一个主要结论能指向真实证据；没有证据的内容明确标为目标、假设或待验证。
- 有流程关系时使用箭头或时间轴；并列事项不伪装成流程。
- 进度条目可说明状态依据；没有分母时不画百分比进度。
- 长卷章节连续、层级清楚，颜色、描边、圆角和留白与本文件一致。
- 所有原案例品牌资产和数字都已替换或确认可用。
