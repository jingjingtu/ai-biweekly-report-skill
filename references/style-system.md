# AI 双周会视觉与绘图规范

## 风格定义

整体语言是“工程控制台式设计汇报”：黑色画布、荧光绿主线、点阵坐标背景、终端式眉题、低圆角数据卡和可扫描的状态标签。视觉必须服务于计划、状态和证据，不能变成赛博装饰。

## 色彩语义

| 角色 | 建议色值 | 用途 |
|---|---|---|
| 画布 | `#030605` | 页面底色 |
| 一级容器 | `#0A1713` | 目标区、章节区 |
| 二级卡片 | `#050B09` | 内容卡、证据卡 |
| 主绿 | `#00F58A` | 目标、完成、关键结论、主路径 |
| 深绿 | `#064D31` | 绿描边、路径底色 |
| 紫 | `#9B7BFF` | Coding、Skill、生成能力 |
| 青 | `#22D3EE` | 验证、连接、跨模块协作 |
| 橙 | `#FF9D32` | 风险、等待、下一阶段 |
| 主文字 | `#F2F7F5` | 标题、关键数字 |
| 次文字 | `#97AAA4` | 正文、说明 |
| 弱文字 | `#5E736C` | 元信息、辅助标注 |

绿色占可见强调的约 70%，紫/青/橙合计不超过 30%。红色仅用于明确失败或阻塞，不作为常规装饰色。

## 字体层级

- 中文：`MiSans`、`PingFang SC`、`Noto Sans SC` 依次回退。
- 英文技术标签：等宽字体 `JetBrains Mono`、`SFMono-Regular`。
- 页面大标题：56–64px / 800。
- 章节标题：34–42px / 700。
- 卡片标题：28–34px / 700。
- 指标：44–56px / 800。
- 正文：24–28px / 400，行高 1.55–1.75。
- 终端眉题与状态标签：24–26px / 600，允许轻微字符间距。
- 标题、正文、流程说明、指标解释等叙事文字不得小于 `24px`。仅“问题 / 风险 / 收益 / 验收”等非叙事微型状态标签可使用 `20–24px`，但容器高度必须为 `34–40px`，文字框填满容器并水平/垂直居中。
- **Figma 文字节点硬规则**：单行文字的节点高度 = `fontSize + 8px`，例如 16px 字号节点高 24px；多行文字统一 `lineHeight = fontSize * 1.6`，节点高度按实际行数计算。禁止创建或保留 `height=1px` 的文字节点。
- 生成 Figma 文本时，必须先加载字体，再设置 `characters / fontSize / lineHeight`，最后设置节点宽高；单行按 `fontSize + 8px` 固定高度，多行按 1.6 倍行高和行数给足高度。

## 网格与间距

- HTML 每页固定 `1920px × 1080px`；左右内边距 `80px`，上下内边距 `64px`。
- 不允许使用 `min-height` 代替固定高度，也不允许内容撑高页面；放不下时新增下一页。
- 主内容使用 12 列思路；常用 4 等分指标、3 等分推进卡、2 列证据区。
- 页面标题与主体间距使用 `40px` 或 `48px`；模块间距使用 `24px`、`32px` 或 `40px`；卡片内边距使用 `24px`、`32px` 或 `40px`。
- 整体布局遵循 `8px` 倍数原则：页面边距、模块宽高、卡片内边距、间距、圆角、坐标位置、图片容器尺寸优先使用 `8` 的倍数。描边允许 `1px`，其余非 8 倍数必须有明确视觉或素材比例原因。
- 空间留白不能过多。安全区内主要内容应形成稳定信息密度；如果主体内容明显不足、大片区域无信息承载，必须补充证据截图、流程关系、状态刻度、图注、对照说明或重新分栏，禁止用空卡片、超大间距或无意义装饰撑版面。
- 内容卡片、证据卡、下一步卡的默认内边距为 `24px 32px 24px 24px`；上/下/左必须保持 24px，右侧可根据视觉平衡扩展到 32px 或 40px，但不得小于 24px。
- 三等分卡片默认 `gap=32px`。不要使用 `space-between` 把三张卡片推到两端制造中间大空白；若业务需要稀疏排列，空白中必须加入连接线、坐标刻度、编号或状态路径等信息型装饰。
- 卡片圆角 8px，大章节圆角 16px。禁止 24px 以上软萌圆角。
- 描边 1px，强调模块可用 2px；阴影只用于主目标框，且必须弱。

## Figma 原生布局结构

生成或整理到 Figma 时，目标不是只还原视觉，而是交付可编辑的原生布局。每个语义模块必须能被设计师一键选中、移动、复用和替换内容。

- 页面根节点必须是 `Root Report Frame`，固定 `1920 × 1080`，使用垂直 Auto Layout 承载 `Header / Main / Footer`。页内安全边距仍按 `80px / 64px` 控制。
- `Header`、`Main`、`Footer`、`Section`、`Module`、`Card`、`MetricCard`、`EvidenceCard`、`NextActionCard`、`TagGroup`、`FlowStep` 都必须是 Auto Layout Frame，不要用普通 Frame 加一堆绝对定位子元素拼出来。
- 同一内容块的背景、描边、标题、正文、编号、状态标签、图标和辅助说明必须放在同一个 Auto Layout Frame 内。不能把背景矩形放在卡片外面，也不能让文字直接散落在页面 Root 下。
- 卡片默认垂直 Auto Layout：`paddingTop=24`、`paddingLeft=24`、`paddingBottom=24`、`paddingRight=32–40`，`itemSpacing=16–24`。卡片宽高可固定，但内部文字和标签必须由 Auto Layout 排列。
- 指标带、三卡布局、标签组默认水平 Auto Layout；三卡之间使用 `itemSpacing=32`，不要用手动坐标摆放。标签较多时使用独立 `TagGroup`，允许换行或拆成两行，但每个标签仍在标签组内。
- 流程图必须拆成 `FlowGroup`：每个步骤是 `FlowStep` Auto Layout，连接线放在 `Connector / ...` 层。连接线可以绝对定位，但必须挂在同一个流程组或连接层内，不能散在页面根节点下。
- 只有点阵背景、跨模块连接线、截图遮罩、装饰性坐标线这类覆盖物可以绝对定位，并且必须命名为 `Overlay / ...`、`Connector / ...` 或 `Grid / ...`。除此之外，正文内容不允许绝对定位散放。
- 从 HTML 导入 Figma 后，如果导入器把内容拆散，必须按 `data-figma-block` 重新整理成上述 Auto Layout 层级，再交付或截图验收。
- 验收时检查层级面板：页面 Root 下不应直接出现大量 `TEXT`、`RECTANGLE`、`LINE`；这些元素应该被包在可读命名的模块 Frame 内。

## Figma 对齐细节

标签、胶囊按钮、流程步骤和页脚页码是最容易“看着差几像素”的地方，必须用结构属性保证对齐，而不是靠手动拖动。

- 标签、按钮和流程步骤容器必须使用水平 Auto Layout，`primaryAxisAlignItems=CENTER`、`counterAxisAlignItems=CENTER`，上下左右内边距按 8px 倍数设置。
- 单行标签文字不要只使用 Hug 文本框。文字节点应固定为容器宽高，并设置 `textAlignHorizontal=CENTER`、`textAlignVertical=CENTER`，这样选中状态、导出和缩放时都不会显得贴边。
- 同一组标签的文字框高度、行高和容器高度必须一致；如果标签宽度不同，仍保持同一高度和同一垂直中心线。
- 页头右侧状态组和页脚页码必须对齐到页面安全区右边界。页码使用固定宽度文字框，内容右对齐；不要靠 spacer 或手动 x/y 造成每页右边界漂移。
- 验收时记录右边界：例如 `1920px` 页面、右侧安全边距 `96px` 时，页脚页码和页头状态组的右边界都应为 `1824px`。
- Figma 生成后必须跑节点级 QA：逐页检查标签文字框是否等于容器宽高、标签文字是否 `CENTER/CENTER`、页头/页脚右边界是否一致、叙事文字是否不小于 `24px`、`20–24px` 微型状态标签是否只承担辅助状态、文本高度是否大于 `1.5px`、所有内容是否在 `1920 × 1080` 根节点内。
- QA 不通过时必须先修复画板再回复用户。不要只说“规则已加入 Skill”，因为 Skill 文本不会自动修复已经生成或由其他流程生成的画板。

## 标志性绘图语言

1. **终端眉题**：`> Qifu B System / biweekly.md`，左上对齐，用主绿等宽字。
2. **点阵坐标**：24–32px 间距、低透明度，只用于封面或章节背景。
3. **能力路径**：深绿横带 + 文本节点 + 箭头，不画复杂流程图。
4. **阶段时间轴**：一条细线连接 3 个节点；当前绿、下一阶段紫、远期橙。
5. **状态卡**：左侧编号与标题，中部动作/证据，右侧状态或数据；不同语义用紫/青/绿细描边。
6. **进度表达**：真实百分比才画进度环/条。没有基线时用状态标签和里程碑数量。
7. **截图**：使用真实界面截图，保持清晰，配 1 句证据型图注；不使用模糊氛围图。

## 视觉发挥模式

当用户希望“不只是整齐”“多一些样式发挥”或要求参考某个既有画板时，可以在基础规范上增强视觉节奏，但必须先提炼参考画板语言，再应用到新版本。

- 先观察参考画板的稳定特征：背景材质、主色比例、标题位置、卡片边框、标签样式、流程箭头、分隔线、编号系统和页脚节奏。
- 表现力来自信息结构，不来自堆装饰。可以增加仪表盘式分区、流程带、状态刻度、发光描边、截图容器和局部高亮，但每一层都要说明一个关系。
- 强视觉页仍要有清晰安全区。主标题、说明、主模块和页脚之间必须有稳定间距，不能贴边、互相压住或因为 Figma 工具栏/画板边缘造成视觉误判。
- 同一页同时出现“要观众做的事”和“团队之后会做的事”时，二者不能同级呈现。观众任务用主卡片；团队动作用低权重流程条、脚注或 Next Action Strip。
- 若创建多个版本，保留已确认版本，在空白处生成新版，并用页名区分 `Condensed`、`Expressive`、`Polished` 等版本状态。

## 厚实视觉版

当用户说“厚实视觉版”“参考之前那种厚实效果”“现在太平 / 太薄 / 不够有层级 / 字体粘连”时，进入厚实视觉版。它不是把普通版加粗，而是用更稳的块面、阶段关系和指标带提升信息压强。

### 触发与命名

- 只要用户要求厚实感或参考此前厚实样张，必须在空白区域生成新版，不覆盖已确认版本。
- Figma 页面命名使用 `Root Report Frame / <主题> 厚实视觉版 / 01`、`02`、`03`。
- 如果同一画板已有 `Condensed`、`Expressive`、`Polished` 等版本，厚实版应放在其右侧或下方的空白区域，并保持三页位置对齐。

### 视觉语言

- 背景仍为近黑 `#030605`，主体使用更厚的深色块面：主容器可用 `#062619`、`#06212A`、`#081812`，内容卡用 `#040A08` 或 `#071611`。
- 不要只用细线框堆卡片。每页至少有一个 60% 以上宽度的主模块，用实底、描边和弱发光形成视觉重心。
- 发光只用于主模块、当前阶段、指标卡或风险/收益卡，透明度保持克制；不能用随机光球填空。
- 标题区保留终端眉题和右侧页码状态，但主体要明显比普通版更“压住画面”：大块面、阶段线、编号、指标卡和路径条共同构成层级。

### 版式模板

- 第 1 页适合“本期判断”：左侧做一张 60% 左右宽度的主判断模块，右侧做 3 张问题/风险/收益卡。左侧主模块和右侧三卡的顶线、底线要基本对齐；不要把主判断拆成多个同权重装饰流程。
- 第 2 页适合“方法架构”：顶部 3 张规则卡，下方放一张全宽示例矩阵或参数表，形成“两层内容就收住”的节奏。只有数据足够且不会挤压呼吸带时才加底部指标卡；否则删除指标带，不要把指标硬塞到页脚上方。
- 第 3 页适合“验证闭环”：上方三步流程，中部两张清单或证据块，下方一条路径条或下一步 Strip。若有“希望大家反馈的 4 件事”，内部处理动作只能降级为流程条或脚注，不能和 4 件事并列成同级卡片。
- 三页都必须形成稳定信息密度。若页面显得空，优先补流程关系、对照说明、真实截图容器、状态刻度或指标带，不用空卡片撑版面。

### 间距与节奏标尺

以下数值来自已确认的 `Root Report Frame / 跨平台 Skill 厚实视觉版 / 01` 与 `/ 02`，适用于 `1920 × 1080` 固定页面；换内容时优先保持比例和节奏，不必机械复制每个坐标。

- 页头保持紧凑：终端眉题约在 `y=58`，标题约在 `y=104`，副标题约在 `y=188`。标题到副标题间距控制在 `6–12px`，副标题到主体间距控制在 `20–40px`，避免普通版那种头重和主体下沉。
- 主体区域从 `y=260–280` 开始，主体底部落在 `y=890–910`。主体到底部页脚线保留 `70–88px` 呼吸带，让页面有收束感，而不是贴着页脚塞满。
- 主体横向使用 `x=80` 到 `x=1840` 的版心宽度。第 1 页推荐左侧主模块约 `1048px`、中间间距 `32px`、右侧卡片约 `680px`；右侧三卡高度约 `199px`，卡片之间 `24px`，三卡整体底线与左侧主模块底线误差控制在 `4px` 内。
- 第 2 页推荐顶部三卡高度约 `240px`，与下方全宽矩阵间距 `32px`；下方矩阵高度约 `344px`，让页面在 `y=893` 左右收住，并把下方留给结论和页码。
- 页脚节奏固定：页脚横线靠近 `y=978–1000`，结论和页码放在其下方同一基线；页码固定宽度并右对齐到 `x=1840`。不要让页码随文本宽度漂移。

### 字体与排版

- 中文标题优先使用 `MiSans Heavy/Bold`、`PingFang SC Semibold`；正文用 Regular/Medium。不要把小正文也设成过重字重。
- 大标题 56–64px，行高至少 `fontSize * 1.2`；章节标题 32–42px，行高至少 `fontSize * 1.25`；正文 24–28px，行高 `fontSize * 1.55–1.75`。
- 解决“字体粘连”优先靠行高、段落间距和文本框高度，不靠继续缩小字号。长中文段落建议一行不超过 34–38 个汉字。
- 单行标签、按钮、流程节点文字仍要填满容器并水平/垂直居中；不同宽度的标签保持同一高度和同一中心线。微型状态标签可以更小，但必须是状态辅助，不能替代标题或正文。

### 厚实版 QA

- 必须截图查看 3 页整体观感：主模块是否足够大、内容是否贴边、主体底部是否在 `y=890–910` 收住、页脚是否保留呼吸带、指标说明是否压底、页脚是否右对齐。
- 节点级检查仍是硬门槛：无画面外元素、无 `height<=1.5px` 文本、无小于 `24px` 的叙事文字、微型状态标签符合 `20–24px` 例外规则、标签文字填满容器并居中、页头状态和页脚页码右边界一致。
- 如果用户指出“样式还是不像参考”或“字体粘连”，不要只修一两个像素；应回到参考图提炼视觉语言，重新调整块面比例、行高、模块主次和指标带。

## 避免事项

- 不使用大面积紫色渐变、霓虹光晕、随机光球。
- 不把每个段落都装进卡片；章节背景与重复内容卡需区分。
- 不做左右各半的营销式 hero。
- 不用纯视觉插画替代真实交付证据。
- 不为了填满页面重复同一项进展。
- 不把多页内容压缩成长页，也不通过缩小到 24px 以下来硬塞内容。
- 不允许文字节点高度为 1px，不允许多行正文使用单行高度。
- 不允许三卡之间出现没有语义、没有装饰、没有连接关系的大块空白。
- 不允许把主反馈项、内部处理动作、证据备注做成同一权重的卡片网格。
- 不允许标签文字用 Hug 文本框悬在容器内，导致看起来没有居中或贴近边缘。
- 不允许页脚页码在不同页面使用不同右边界。
