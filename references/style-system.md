# AI 双周会视觉规范

## 风格目标

整体语言是“工程控制台式设计汇报”：近黑画布、荧光绿主线、点阵坐标、终端眉题、低圆角数据卡和可扫描的状态标签。技术感必须说明目标、状态、证据或关系，不能成为装饰。

当用户指定视觉样例时，[视觉样例审查](sample-standard.md) 是版式证据源，本文件提供可执行的视觉 token。B 端汇报的内容顺序由 [B 端历史汇报内容标准](b-end-content-standard.md) 决定；视觉参考只能改变承载方式，不能重排问题推演。

## 色彩语义

| 角色 | 色值 | 用途 |
|---|---|---|
| 画布 | `#030605` | 页面底色 |
| 一级容器 | `#0A1713` | 目标区、章节区 |
| 二级卡片 | `#050B09` | 内容卡、证据卡 |
| 主绿 | `#00F58A` | 主线、关键结论、核心路径 |
| 紫 | `#9B7BFF` | 工程化、生成与 Skill 能力 |
| 青 | `#22D3EE` | 验证、连接和协作 |
| 橙 | `#FF9D32` | 风险、等待和下一阶段 |
| 主文字 | `#F2F7F5` | 标题、关键数字 |
| 次文字 | `#A6B8B2` | 正文、说明 |
| 弱文字 | `#789088` | 元信息、图注和页脚 |

颜色只表达内容类别。`DONE / VERIFY / BLOCKED / NEXT / BASELINE` 使用独立文字标签、图标或边框样式，不能仅靠颜色表达。正文与背景保持足够对比；弱文字不能承担关键结论。

## 字体层级

- 中文：`MiSans`、`PingFang SC`、`Noto Sans SC`。
- 英文技术标签：`JetBrains Mono`、`SFMono-Regular`、`Menlo`。
- 页面标题：56–64px / 800。
- 章节标题：34–42px / 700。
- 卡片标题：28–34px / 700。
- 指标：44–56px / 800。
- 正文：24–28px / 400，行高 1.55–1.75。
- 眉题与状态标签：24–26px / 600。
- 仅非叙事微型状态标签允许 20–24px；标题、正文、指标解释和图注不得小于 24px。

## 页面骨架

- `slides` 固定 1920 × 1080；水平安全边距 80px，垂直安全边距 64px。
- `long-scroll` 固定 1920px 宽、总高度自适应；水平安全边距 72–96px，章节上下留白 80–160px，章节之间连续衔接而非出现灰色页面缝隙。章节高度由内容决定，不强制补齐 1080px。
- `slides` 固定 `Header / Main / Footer`；页脚页码右边界与页头状态一致。`long-scroll` 以章节为单位，可隐藏重复页脚并保留章节编号。
- 页面标题到主体使用 40px 或 48px；模块间距使用 24px、32px 或 40px。
- 卡片默认内边距 `24px 32px 24px 24px`；圆角 8px，大容器圆角 16px。
- 三等分卡片间距 32px；2–4 列指标带按数量等分，不为空位补卡。
- 主要尺寸优先使用 8px 倍数，描边允许 1px。

## Layout Profile

- `cover-summary`：大结论与最多 3 个辅助模块。
- `single-focus`：一张主模块与可选侧栏。
- `two-column`：约 60/40 分栏，中间间距 32px。
- `three-card-matrix`：三张同级卡与一张全宽支撑模块。
- `timeline-evidence`：阶段路径、证据与下一步。
- `feedback-loop`：反馈任务为主，内部处理流程为辅。
- `before-after`：旧流程与新流程对照，下接阶段或能力变化。
- `portfolio-progress`：按能力族分组的全宽进度条目，右侧使用状态锚点。
- `gallery-evidence`：代表案例放大与成果画廊，所有图片带证据图注。

生成前先确定 Layout Profile。单页只使用一种主布局；内容放不下时换版式或拆页。

## 版式多样性门禁

当用户提供了多种版式样例、明确要求版式变化，或 `long-scroll` 含 4 个以上主要章节时，生成前必须记录 `sectionLayoutPlan`：

```yaml
- section: <章节名>
  layoutProfile: <本章主布局>
  visualAnchor: <大标题 / 主证据 / 对照 / 路线 / 账本等>
  evidenceForm: <截图 / 数字 / 规则 / 流程 / 状态>
  differsFromPrevious: <结构差异说明>
```

- 4 个以上主要章节至少采用 3 种与内容匹配的 Layout Profile；材料只支持单一结构时可以减少，但必须在交付说明原因。
- 相邻主要章节不得重复相同的“标题位置 + 主体分栏 + 卡片数量 + 结论条”骨架。
- 改颜色、改标题、交换卡片文案或把三卡改成四卡，不算版式变化。
- 版式变化应来自内容关系：总结用非对称主视觉，过程变化用 `before-after`，依赖与阶段用 `timeline-evidence`，故障推演用诊断剖面或 `feedback-loop`，验证结果用账本/清单，下一步用里程碑。
- 连续长卷只统一色彩、字体、边距和状态语义；章节标题位置、视觉重心、分栏比例和证据承载方式允许变化。
- Figma 节点命名应体现实际布局职责，例如 `Hero / Asymmetric`、`Compare / Old and New`、`Roadmap / Ladder and Lanes`，不能所有章节都只叫 `Header / Main / Footer`。

推荐的 `b-end-transformation` 长卷组合是：`cover-summary` → `before-after` → `timeline-evidence` 或平台路线 → 诊断剖面/`feedback-loop` → 验证账本与里程碑。它是选择示例，不是固定五段模板；应随当前证据删减或替换。

## 信息密度

- 留白用于分组、节奏和聚焦，不追求“填满页面”。
- 禁止空卡片、重复信息或无意义装饰占位。
- 当三张卡片内容差异很大时，不强制拉成巨大的等高卡；可以使用紧凑卡片加全宽证据区。
- 内容少时采用 `cover-summary` 或 `single-focus`，不要用大网格制造空洞。
- 内容多时拆页，不能缩小到 24px 以下或贴近页脚。

## 标志性语言

1. 终端眉题：品牌与汇报类型来自输入，例如 `> AI Design / biweekly.md`。
2. 点阵坐标：24–32px 间距、低透明度，只用于封面或章节背景。
3. 能力路径：深绿横带、文本节点和箭头，不画无意义复杂流程。
4. 阶段时间轴：当前、下一步和远期使用标签区分，颜色表达内容类别。
5. 进度表达：只有真实百分比才画进度条；没有基线时使用状态和里程碑。
6. 截图证据：使用清晰真实截图，并配一句“证明了什么”的图注。

## 表现力模式

用户要求更有设计感或参考既有画板时，先提炼背景材质、标题位置、卡片边框、编号、流程和页脚节奏，再生成独立新版，不覆盖已确认版本。

“厚实视觉版”至少包含一个占主体宽度 60% 左右的主模块，使用更稳定的实底块面、阶段线和指标带形成重心。发光只用于主模块或关键节点，不能用随机光球填空。

## 长卷章节节奏

- 首章：终端眉题 + 大标题 + 绿色关键短语 + 一句解释；可加指标带，但不堆完整进度清单。
- 中段：在工作流、路径、进度、案例之间交替使用“图像主导”和“清单主导”章节，避免连续三段同构卡片。
- 证据段：真实截图或产物占主要面积，文字负责标注输入、过程、结果和证明点。
- 收束段：使用全宽结论条或三张下期里程碑卡，不用一句口号代替交付物与验收标准。
- 长卷不追求所有章节等高；只有存在真实依赖时才用箭头连接。

## 避免事项

- 不使用大面积紫色渐变、随机霓虹光球或纯装饰插画。
- 不把每段文字都放进等权卡片。
- 不用空卡片或重复信息填充画面。
- 不把观众反馈项、内部处理动作和证据备注做成同级网格。
- 不使用不完整页码。
- 不让品牌名称、周期或阶段硬编码在模板中。
- 不以缩小字号解决溢出。

Figma 的 Auto Layout、文字节点和结构 QA 规则见 [Figma 输出规范](figma-output.md)。
