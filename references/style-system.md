# AI 双周会视觉规范

## 风格目标

整体语言是“工程控制台式设计汇报”：近黑画布、荧光绿主线、点阵坐标、终端眉题、低圆角数据卡和可扫描的状态标签。技术感必须说明目标、状态、证据或关系，不能成为装饰。

当用户指定视觉样例时，[视觉样例审查](sample-standard.md) 是版式证据源，本文件提供可执行的视觉 token。B 端汇报的内容顺序由 [B 端历史汇报内容标准](b-end-content-standard.md) 决定；视觉参考只能改变承载方式，不能重排问题推演。

## 色彩语义

| 角色 | 色值 | 用途 |
|---|---|---|
| 画布 | `#030605` | 页面底色 |
| 一级容器 | `#0A1713` | 目标区、章节区 |
| 二级卡片 | `#050B09` | 内容卡、证据卡 |
| 主绿 | `#00F58A` | 主线、关键结论、核心路径 |
| 紫 | `#9B7BFF` | 工程化、生成与 Skill 能力 |
| 青 | `#22D3EE` | 验证、连接和协作 |
| 橙 | `#FF9D32` | 风险、等待和下一阶段 |
| 粉色 | `#F06BD8` | 差异、分支、例外与需要注意的局部标记；B 端汇报不使用红色 |
| 主文字 | `#F2F7F5` | 标题、关键数字 |
| 次文字 | `#A6B8B2` | 正文、说明 |
| 弱文字 | `#789088` | 元信息、图注和页脚 |

颜色只表达内容类别。`DONE / VERIFY / BLOCKED / NEXT / BASELINE` 使用独立文字标签、图标或边框样式，不能仅靠颜色表达。正文与背景保持足够对比；弱文字不能承担关键结论。

标题颜色门禁：

- B 端首章和章节大标题使用主文字白为主体，只允许主绿强调关键判断短语。
- 红色不得用于任何 B 端汇报文字、描边、填充或渐变色标；粉色承担原先“问题/差异/阻塞提示”的局部定位角色。
- 问题、失败和阻塞优先用 24–32px 眉题、状态标签、局部描边、差异编号或一处短注释表达；粉色只承担定位，不承担章节主视觉。
- 若标题内容本身是问题判断，仍使用“白色问题陈述 + 绿色核心结论”，不能用整段红字制造紧张感。

## 字体层级

- 中文：`MiSans`、`PingFang SC`、`Noto Sans SC`。
- 英文技术标签：`JetBrains Mono`、`SFMono-Regular`、`Menlo`。
- 长卷首章主标题：64–88px / 800。
- 长卷章节大标题：48–64px / 700–800。
- 独立页面标题：56–64px / 800。
- 卡片标题：28–34px / 700。
- 指标：44–56px / 800。
- 正文：24–28px / 400，行高 1.55–1.75。
- 眉题与状态标签：24–26px / 600。
- 所有可见文字，包括装饰性编号、眉题、状态、图注、坐标、页脚和数据来源，均不得小于 24px。空间不足时删减文字、扩大模块、换布局或拆章节，不得缩字。

## 页面骨架

- `slides` 固定 1920 × 1080；水平安全边距 80px，垂直安全边距 64px。
- `long-scroll` 固定 1920px 宽、总高度自适应，并且只有一个连续的根画布/根 Frame；水平安全边距 72–96px，章节上下留白 80–160px。章节是根画布内连续排列的子 Frame，可用背景色变化、细线、编号或留白分节，但不能出现灰色拼页缝隙或彼此分离的独立画板。章节高度由内容决定，不强制补齐 1080px。
- 匹配用户 B 端历史稿时默认使用 80px 左右安全边距；所有章节的眉题、章节标题、说明文字和一级内容容器必须共享同一个绝对左坐标，右边界也保持一致。
- 章节标题统一左对齐。除非用户明确指定另一套视觉系统，不使用居中标题、右对齐标题、独立编号大方块挤占标题基线或左右交替标题。
- `slides` 固定 `Header / Main / Footer`；页脚页码右边界与页头状态一致。`long-scroll` 以章节为单位，可隐藏重复页脚并保留章节编号。
- 页面标题到主体使用 40px 或 48px；模块间距使用 24px、32px 或 40px。
- 卡片默认内边距 `24px 32px 24px 24px`；圆角 8px，大容器圆角 16px。
- 三等分卡片间距 32px；2–4 列指标带按数量等分，不为空位补卡。
- 主要尺寸优先使用 8px 倍数，描边允许 1px。

## Layout Profile

- `cover-summary`：大结论与最多 3 个辅助模块。
- `single-focus`：一张主模块与可选侧栏。
- `two-column`：约 60/40 分栏，中间间距 32px。
- `three-card-matrix`：三张同级卡与一张全宽支撑模块。
- `timeline-evidence`：阶段路径、证据与下一步。
- `feedback-loop`：反馈任务为主，内部处理流程为辅。
- `before-after`：旧流程与新流程对照，下接阶段或能力变化。
- `portfolio-progress`：按能力族分组的全宽进度条目，右侧使用状态锚点。
- `gallery-evidence`：代表案例放大与成果画廊，所有图片带证据图注。

生成前先确定 Layout Profile。单页只使用一种主布局；内容放不下时换版式或拆页。

## 版式多样性门禁

当用户提供了多种版式样例、明确要求版式变化，或 `long-scroll` 含 4 个以上主要章节时，生成前必须记录 `sectionLayoutPlan`：

```yaml
- section: <章节名>
  layoutProfile: <本章主布局>
  visualAnchor: <大标题 / 主证据 / 对照 / 路线 / 账本等>
  evidenceForm: <截图 / 数字 / 规则 / 流程 / 状态>
  alignmentBaseline: <标题与一级内容左坐标，B 端历史稿默认 80>
  decorationMotifs: <本章使用的 1–3 种装饰语法及用途>
  differsFromPrevious: <结构差异说明>
```

- 4 个以上主要章节至少采用 3 种与内容匹配的 Layout Profile；材料只支持单一结构时可以减少，但必须在交付说明原因。
- 相邻主要章节不得重复相同的“主体分栏 + 主视觉比例 + 卡片数量 + 结论条”内容骨架；标题系统保持稳定。
- 改颜色、改标题、交换卡片文案或把三卡改成四卡，不算版式变化。
- 版式变化应来自内容关系：总结用非对称主视觉，过程变化用 `before-after`，依赖与阶段用 `timeline-evidence`，故障推演用诊断剖面或 `feedback-loop`，验证结果用账本/清单，下一步用里程碑。
- 连续长卷统一色彩、字体、边距、标题左基线和状态语义；视觉重心、分栏比例、证据承载方式与模块组合可以变化。
- Figma 节点命名应体现实际布局职责，例如 `Hero / Asymmetric`、`Compare / Old and New`、`Roadmap / Ladder and Lanes`，不能所有章节都只叫 `Header / Main / Footer`。
- 版式变化发生在章节标题下方，至少覆盖下列六个维度中的三个：主容器比例、视觉重心、分栏比例、证据载体、阅读方向、模块组合/背景分区。只改变装饰但结构不变不能算新版式。
- 4 个以上章节不仅要覆盖至少 3 种 Layout Profile，还要避免连续三章都使用“上标题 + 下方等宽卡片矩阵”。

推荐的 `b-end-transformation` 长卷组合是：`cover-summary` → `before-after` → `timeline-evidence` 或平台路线 → 诊断剖面/`feedback-loop` → 验证账本与里程碑。它是选择示例，不是固定五段模板；应随当前证据删减或替换。

## 用户 B 端历史稿审美基准

- **秩序先于变化**：先固定 1920px 画布、80px 左右边距、标题左基线、1760px 一级内容宽度和 8px 基础网格，再设计章节内部变化。
- **标题形成连续阅读线**：眉题、标题、说明均左对齐；标题使用白色为主、只把关键结论短语标绿，避免整句多色、红色大标题和左右跳动。
- **块面建立层级**：优先使用一个全宽主容器或清晰的主次分栏，再在内部放步骤、截图、规则或列表；不要让许多小卡片直接漂浮在黑底上。
- **对齐必须可测量**：同级卡片顶边与底边一致，列宽和间距来自统一网格，状态标签共享右边线，箭头位于模块中心线；禁止依靠目测制造近似对齐。
- **横向组件保留呼吸感**：路径条、流程条和组合方式条的首尾内容保留对称安全内边距，最小为 24px；有剩余空间时用整体居中或等距分配，不能只把内容从左边开始堆放。流程箭头位于两个节点之间及轨道垂直中心；状态芯片内的状态与说明在水平、垂直方向都居中，四周保留可见内边距。
- **色彩比例克制**：主绿承担主结论和关键路径；青、紫、粉色只用于验证、工程和差异等局部标签/描边；橙色只在明确的下一阶段语义中少量使用，不使用大面积高饱和色块争夺标题。
- **表面建立层级**：大章节和主证据区优先使用近黑、深绿、深蓝或紫黑的低对比渐变表面，配合 1px 描边、局部辉光或材质差异建立前后层级；不能全卷只留透明框。每章最多一个主渐变表面和一处局部辉光，标题区保持可读。
- **辅助元素表达关系**：有因果、依赖、分支、汇聚或阶段关系时，使用箭头轨道、时间轴、分支连接、汇聚节点、步骤编号或证据引线表达；并列信息不伪装成流程，辅助元素不得遮挡正文。
- **变化来自内容载体**：可在全宽路径条、三阶段栅格、大圆角问题场、架构分层、证据主次分栏、进度长列表之间切换，但章节标题系统、外边距和一级容器边界保持不变。
- **装饰服从网格**：终端眉题、细分隔线、低透明网格、编号、箭头和局部辉光只能贴合既有基线或容器边缘；不使用悬浮装饰破坏对齐。

## 克制的装饰与丰富度

装饰必须帮助定位、分组、连接、强调或表达技术语境。每个主要章节选择 1–3 种装饰语法，并在 `sectionLayoutPlan` 记录 `decorationMotifs` 与用途；相邻章节不得使用完全相同的装饰组合。

可选语法：

- **结构型**：章节编号轨道、坐标刻度、括号/切角容器、阶段线、连接箭头、平台泳道、数据刻度。
- **背景型**：低透明点阵、细网格、单一方向光晕、局部扫描线、深绿/深蓝分区；同一章节最多使用两种。
- **标注型**：终端路径、状态芯片、证据编号、注释引线、结论下划线、局部高亮框。
- **证据型**：截图叠层、浏览器/设备边框、代码片段、规则清单、对比遮罩；必须有“证明了什么”的图注。

丰富度门槛：

- 每章至少有一个主视觉锚点和一种结构型或证据型装饰；纯文字卡片矩阵不得作为连续长卷的默认章节。
- 每章最多一个高亮光晕、最多两种强调色、最多三种装饰语法；装饰不得遮挡文字或模拟不存在的数据。
- 全卷保留一个重复母题形成一致性，例如终端路径、章节编号或细网格；其余装饰随内容变化。
- 章节背景可在近黑、深绿、深蓝之间克制切换，但文字对比度、颜色语义和整体品牌调性保持一致。
- 优先用尺寸、方向、叠层、裁切、连线和留白形成变化；不要靠堆图标、加阴影或放随机几何图形制造“丰富”。
- “丰富”不等于标题位置变化。使用历史 B 端样式时，标题系统与一级边界保持固定，变化只进入内容模块、证据比例、局部色彩和装饰细节。

## 信息密度

- 留白用于分组、节奏和聚焦，不追求“填满页面”。
- 禁止空卡片、重复信息或无意义装饰占位。
- 当三张卡片内容差异很大时，不强制拉成巨大的等高卡；可以使用紧凑卡片加全宽证据区。
- 内容少时采用 `cover-summary` 或 `single-focus`，不要用大网格制造空洞。
- 内容多时拆页，不能缩小到 24px 以下或贴近页脚。

## 标志性语言

1. 终端眉题：品牌与汇报类型来自输入，例如 `> AI Design / biweekly.md`。
2. 点阵坐标：24–32px 间距、低透明度，只用于封面或章节背景。
3. 能力路径：深绿横带、文本节点和箭头，不画无意义复杂流程。
4. 阶段时间轴：当前、下一步和远期使用标签区分，颜色表达内容类别。
5. 进度表达：只有真实百分比才画进度条；没有基线时使用状态和里程碑。
6. 截图证据：使用清晰真实截图，并配一句“证明了什么”的图注。

## 表现力模式

用户要求更有设计感或参考既有画板时，先提炼背景材质、标题对齐与基线、卡片边框、编号、流程和页脚节奏，再生成独立新版，不覆盖已确认版本。

“厚实视觉版”至少包含一个占主体宽度 60% 左右的主模块，使用更稳定的实底块面、阶段线和指标带形成重心。发光只用于主模块或关键节点，不能用随机光球填空。

## 长卷章节节奏

- 首章：终端眉题 + 大标题 + 绿色关键短语 + 一句解释；可加指标带，但不堆完整进度清单。
- 中段：在工作流、路径、进度、案例之间交替使用“图像主导”和“清单主导”章节，避免连续三段同构卡片。
- 证据段：真实截图或产物占主要面积，文字负责标注输入、过程、结果和证明点。
- 收束段：使用全宽结论条或三张下期里程碑卡，不用一句口号代替交付物与验收标准。
- 长卷不追求所有章节等高；只有存在真实依赖时才用箭头连接。

## 避免事项

- 不使用大面积紫色渐变、随机霓虹光球或纯装饰插画。
- 不把每段文字都放进等权卡片。
- 不用空卡片或重复信息填充画面。
- 不把观众反馈项、内部处理动作和证据备注做成同级网格。
- 不使用不完整页码。
- 不让品牌名称、周期或阶段硬编码在模板中。
- 不以缩小字号解决溢出。
- 不把每个章节做成相同的“上方标题 + 三张圆角卡片 + 底部结论条”。
- 不使用小于 24px 的所谓微型标签来换取信息密度。

Figma 的 Auto Layout、文字节点和结构 QA 规则见 [Figma 输出规范](figma-output.md)。
