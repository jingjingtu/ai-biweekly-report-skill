# 测试与验收

## 每次交付

1. 运行 `scripts/validate-report.mjs`。
2. 浏览器可用时按 `format` 检查：`slides` 逐页检查 1920 × 1080；`long-scroll` 检查 1920px 宽整卷与章节衔接。
3. Figma 输出存在时执行节点级 QA。
4. 记录未完成的验证，不把“生成成功”等同于“验收通过”。

用户要求审查时，除本文件的交付验收外，还必须执行 [五角色审查清单](review-checklist.md)。

## 静态校验项

- 页面数量、编号和总页数一致。
- 不存在未替换模板变量、Lorem、`XX%` 或 `xx月xx日`。
- `data-figma-block` 唯一且非空。
- `slides` 页面 CSS 固定 1920 × 1080；`long-scroll` 固定 1920px 宽且章节高度自适应，不用固定最小高度填充空白。
- 所有可见文字的计算字号均不小于 24px，包括眉题、标签、图注、状态、编号、数据来源和页脚。
- 实际指标存在来源与统计截止日期。

## 视觉校验项

- 无文字溢出、裁切或重叠。`slides` 不依赖页内滚动；`long-scroll` 只允许文档级纵向滚动。
- 一页只有一个主要判断，标题与证据关系清楚。
- 没有大面积无信息承载的空卡片；内容较少时优先换更紧凑版式。
- 用户要求版式变化或提供多种样例时，核对 `sectionLayoutPlan`：4 个以上主要章节至少出现 3 种主布局，相邻章节的内容分栏比例、视觉锚点、证据载体和模块组合不能全部相同。仅颜色、文案或卡片数量不同判为版式重复。
- 用户 B 端历史稿样式下，所有章节标题必须左对齐并共享同一绝对 `x` 坐标；眉题、说明和一级内容容器使用相同左边线。标题居中、右对齐或左右交替直接判为失败。
- 长卷只有一个连续根画布/根 Frame；每个主要小节都有 48px 以上大标题和内容区，章节之间没有拼页缝隙或散落画板。
- 每章至少有一个主视觉锚点以及一种结构型或证据型装饰；每章装饰语法为 1–3 种，背景型不超过两种、强调色不超过两种，相邻章节装饰组合不完全相同。
- 4 个以上章节不得连续三章使用“上标题 + 等宽卡片矩阵”；版式差异至少覆盖主容器比例、视觉重心、分栏比例、证据载体、阅读方向、模块组合/背景分区中的三个维度。
- 同级模块的顶/底边线、列宽、间距和状态标签右边线通过坐标检查；超过 1px 的无意偏差必须修复。
- 页头、主体和页脚位置稳定，页码右边界一致。
- 颜色按内容类别使用，状态不依赖颜色辨识。
- 弱文字仍具备可读性；正文与背景建议达到 WCAG AA 常规文本对比度。

## 回归场景

- 最小输入：只有周期、结论和一项下一步。
- 缺失数据：指标无基线，必须显示“待采集基线”。
- 密集输入：6 项以上进展，验证自动拆页与编号。
- 超长标题：长中文、英文路径与中英文混排。
- 三页浓缩版。
- `management` 与 `project-team` 的信息优先级差异。
- 无浏览器：HTML 静态校验通过并标记视觉检查待完成。
- 无 Figma 权限：内容和 HTML 仍完成。
- 重复内容块名称：渲染器生成唯一标识。
- 恶意或特殊字符：`<`、`>`、`&`、引号不能破坏 HTML。
- 标准样例长卷：`format: long-scroll`、原型明确、章节无灰色拼页缝隙。
- 标准样例事实纪律：样例数字没有来源时不会出现在新报告的实际指标中。
- B 端内容优先级：更换视觉原型不会改变“变化—问题—根因—规则—复验—沉淀—下一步”的因果顺序。
- 背景素材边界：`00 背景.png` 只提供 `#030605` 画布色，不会生成任何内容结论。
- 原始参考资产：`assets/visual-references/` 中存在 5 张其他团队视觉图和 7 张 B 端历史图；生成记录能指出实际审查的原图、复用项和舍弃项。
- 连续长卷：单一根画布内存在 4 个以上带大标题的连续章节，无独立页面拼接缝。
- 字号下限：任意可见文字设置为 23px 时必须验收失败。
- 装饰丰富度：缺少主视觉锚点、整章只有同构卡片，或相邻章节装饰组合完全相同时必须验收失败。
- B 端标题基线：任一章节标题改为居中、右对齐或偏离公共左坐标时必须验收失败。
- B 端标题颜色：任一 `fontSize >= 48px` 的章节标题使用红色分段或大面积红色底块时必须验收失败；问题章节仍应使用白色主体与主绿关键词。
- 成熟度门槛：一次生成成功不能被标记为稳定、可迁移或规模复用。

## 标准样例一致性

使用标准样例时，除通用视觉检查外，还要逐项执行 [样例一致性验收](sample-standard.md#样例一致性验收)。验收记录至少说明：采用了哪个样例原型、复用了哪些结构、舍弃了哪些个案元素，以及每个实际数字的来源。

B 端任务还要执行 [B 端内容一致性验收](b-end-content-standard.md#一致性验收)。内容标准优先于视觉样例。

## Skill 包校验

- `SKILL.md` frontmatter 名称、描述和命名规则有效。
- 所有从 `SKILL.md` 链接的 reference、asset 和 script 都存在。
- 原始视觉参考索引中的 12 个 PNG 均存在，尺寸与索引一致。
- 示例 JSON 可以被渲染并通过静态校验。
- 仓库 CI 应执行上述 smoke test。
