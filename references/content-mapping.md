# 内容与模块映射

## 输入整理

先把材料整理成以下字段：

```text
周期：
一句话结论：
北极星目标：
年度目标值：
当前阶段：
本期动作：
本期交付物：
验证证据：
问题与取舍：
下期动作：
待采集数据：
```

## 内容选择模块

| 内容特征 | 使用模块 | 写作重点 |
|---|---|---|
| 目标与方法论 | 主目标框 + 能力路径 | 为什么做、最终形成什么能力 |
| 2–4 个目标值 | 四等分指标带 | 明确标记目标值而非当前成绩 |
| 3 个阶段 | 时间轴 + 三阶段卡 | 当前/下一步/远期的门槛关系 |
| 2–4 项本期推进 | 状态卡 | 动作、交付物、证据、状态 |
| 有界面或文件证据 | 截图证据区 | 图注写证明了什么 |
| 有前后变化 | Before/After 对照 | 强调设计判断与变化 |
| 有复用链路 | 流程带 | 输入、生成、校验、输出、迭代 |
| 有风险或未解决事项 | 问题与取舍表 | 不回避代价，给出处理边界 |
| 下期计划 | 3 张 Next 卡 | 动作必须带可验收交付物 |

## 双周会默认叙事

1. **目标不变**：一句话重申北极星，不展开全年背景。
2. **本期变化**：说明从上一周期推进到了什么状态。
3. **三项证据**：每项必须能指向文件、组件、页面、报告或真实项目。
4. **当前缺口**：指出尚未验证的范围和数据。
5. **下一周期**：给出 2–3 项可验收动作。

## 三页浓缩版叙事

当用户要求“浓缩一下”“只要 3 页 PPT”“空白处生成 3 页版本”时，优先使用下面的三页逻辑，而不是把完整双周结构塞进三页。

1. **本期判断**：用一句话说明本期真正变化，不写流水账。页面可以包含 `一句话结论 + 3 个关键数字/状态 + 一条路径`。
2. **做了什么 / 体验节奏**：把动作按用户理解路径重组，例如 `入口可感知 → 操作有仪式 → 等待有反馈 → 结果可理解`，不要只按任务清单排列。
3. **验证入口 / 反馈闭环**：把扫码、试用、反馈和下一步处理讲清楚。观众需要做的事用大卡片突出；团队收到反馈后的处理动作降级为流程条或说明带。

三页版必须保留信息密度，但每页只讲一个判断。若用户要求更有设计感，可以用更强的视觉节奏和分区，但不能牺牲标题可读性、卡片间距和语义层级。

## 语义层级规则

同一页面中，必须先判断每组信息属于哪一层：

| 层级 | 典型内容 | 推荐表现 |
|---|---|---|
| 观众需要记住的结论 | 本月判断、关键变化、阶段结果 | 大标题、主卡片、核心数字 |
| 观众需要验证或反馈的问题 | 入口是否清楚、等待是否舒适、结果是否看懂 | 2–4 张重点卡片 |
| 团队内部后续动作 | 整理反馈、回归验证、排期提审 | 流程条、低权重说明带、Next 标注 |
| 背景或辅助证据 | README、截图、版本号、路径说明 | 小标签、图注、弱描边卡片 |

不要把不同层级内容放进同一个等权网格。尤其是“反馈问题”和“反馈后的处理流程”必须分开表现，否则观众会误以为所有卡片都是同一任务。

## 状态词典

- `DONE / 已完成`：交付物存在，且已检查。
- `VERIFY / 验证中`：已生成或已迁移，但仍需真实场景验证。
- `BLOCKED / 受阻`：存在明确外部依赖，必须写依赖对象。
- `NEXT / 下一步`：尚未开始或下一周期计划。
- `BASELINE / 待采集`：需要补充时长、复用、返工或覆盖数据。

## 数据纪律

- 计划数字保留，并标注 `YEAR-END TARGET`。
- 实际数字必须能追溯到用户材料或可验证文件。
- 不知道完成率时，不从任务数量推算百分比。
- 可以展示“3 个模块”“2 份真实页面”“9 张图片”等已验证计数。
- 效率提升没有前后基线时，写“已建立采集口径”，不写“提效 XX%”。

## Figma 内容块标记

所有重复卡片必须在 HTML 中使用独立、唯一、可读的中文名称：

```html
<article class="card" data-figma-block="组件库迁移">...</article>
<div class="proof" data-figma-block="图片嵌入">...</div>
```

不要把整行卡片只标成一个内容块，也不要把背景和文字分别放进不同内容块。
